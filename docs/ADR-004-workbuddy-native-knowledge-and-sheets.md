# ADR-004：WorkBuddy 原生知识与智能表格的条件切换

日期：2026-10-30。基线：`d7dd392ffe5367f6114391096bad38da3d23a13d`。
决策状态：目标方向已认可；原生覆盖验收尚未通过，保留兼容入口。

用户后续确认：WorkBuddy 原生能力可实现，但当前企业版未开通、无法演示；GitHub App 尚未创建，Owner 测试资料与第二位测试同事暂缺。本轮按用户要求完成代码与联调准备，保留这些真实验收项，不反复尝试开通或扩大权限。

## 决策

工作人员知识优先由 WorkBuddy 资料库／授权企业知识源承接；普通运营查询优先由原生企业微信连接器承接。选手提交维持独立 Arena MCP，Arena 负责认证、文件规则、截止、版本、GitHub、登记、恢复和审计。工单身份与状态转换继续受后端控制。

本轮实现原生候选提示及五项 Skills、配置诊断、真实提交演练驱动和 26 项真实 Agent 题集。验收缺口存在时维持当前路由；不删除 `staff_mcp.py`、`policy.py`、`tickets.py`、`outbox.py`。

## 当前读取的证据

| 检查 | 2026-10-30 观察 | 结论 |
| --- | --- | --- |
| WorkBuddy 客户端 | UI 显示 V5.9.3，有资料库与原生企业微信连接器入口 | 仅证明桌面入口存在 |
| 原生企微 B01 | 在原 `test机器人` 私聊发出只读请求，指定原生连接器且排除 Arena MCP；最终回复明确未完成查询，报告机器人文档使用权限过期 | 原生查表不通过，待恢复原测试范围授权；回复中的原因是 Agent 报告，尚无原生后台执行日志独立核验 |
| Arena 本机 CLI | 原表与 v0.3 沙盒初始返回 `893999`；同一机器人重新换取 CLI Token 后，原测试表读一条记录成功 | 本机 Arena 读取恢复，不等于 WorkBuddy 连接器恢复 |
| 恢复后只读复核 | 原测试表读到 3 个作品，公开结果核对 H-001；v0.3 沙盒 1 个虚构作品和五表 schema 通过 | 原表未写入，沙盒未改动 |
| 原生知识 | 没有经 Owner 确认的四类测试资料和资料源绑定 | 未执行 A 实验 |
| 双人验证 | 没有第二名独立企微账号演练证据 | 未执行，不能推出多人隔离 |
| GitHub | 连接器读取代码仓库元数据为 public；四项 GitHub App 环境配置缺失 | 不改仓库可见性；真实作品写入未执行 |

本机新 Token 只保存于 Windows 用户环境，未输出、写文件或复制进 WorkBuddy。原有机器人身份未变。已运行的宿主可能保留旧进程环境；本机后续验证显式从用户环境读取当前 Token，原生连接器则需走其自己的授权入口。

`893999` 是 CLI 的共享兜底码，不能单凭它认定权限过期；本轮“换取 Token 后读表恢复”是实测事实。参考 [官方 CLI 错误格式](https://github.com/WecomTeam/wecom-cli/blob/main/docs/cli-reference.md)。WorkBuddy 回复报告的过期状态属于另一条接入路径。

## 通过条件和回退

按 [真实题集](../evals/workbuddy_cases.md) 完成 K01–K10、S01–S10，补齐实际工具日志和来源对照；通过两用户数据与会话隔离；知识版本可追踪。只有满足这些条件后才审核原生包、装载同一 commit、停止重复查询。

切换异常时恢复当前兼容 Skill 包和已验证的只读 MCP。云端产生新作品版本后先对账，不能用旧 SQLite 覆盖云端。资料库、表格、GitHub 分别承担知识、结构化业务状态和作品证据，不新增同步知识库服务。
