# ADR-002：权威台账与故障恢复

状态：实现与本地故障测试；真实写回以验收报告为准。日期：2026-10-28。

作品文件及 SUBMISSION.json 的版本证据以 GitHub tag 为准；作品、版本、值班、反馈与工单以智能表格为业务台账。
规则及 Skills 以 Git 发布包为准，ima 只能消费已发布副本。
本地 Store/LocalGitWriter 保留为演练和回退适配器，CloudBridge 不可与 SmartSheetRegistry 同时运行。

提交由服务端分配版本。调用方可指定 submission_id，同一 ID 只能绑定同一队伍和内容/标题/说明。
先持久化 planned 操作，再写 Git，获得 tag/SHA 后登记版本、更新最新指针。
表格不是事务数据库，登记拆分失败由同一请求重试或 `arena reconcile` 补齐。
对账只读取既有 Git 证据并补登记，不重新推送作品。

操作日志只保存执行所需的提交元数据和阶段，不保存文件正文、明文凭据或完整业务镜像。
Git 写成功但进程在更新操作日志前退出时，通过 tag 内的 SUBMISSION.json 识别原提交。
GitHub 分支已更新但 tag 尚未建立时，可从该队目录的元数据恢复 tag。
未写入 Git 的 planned 操作须提供原文件及 submission_id 重试；不会假称已完成自动上传恢复。
tag 或内容证据冲突保留 pending，交人工复核。

一个数据目录允许一个写进程；服务内异步锁与操作日志文件锁共同防止同一实例目录重复写入。
多台机器共享一个作品仓库/表格仍需分布式协调，当前不支持无协调的多实例提交。

系统字段由 Arena 写入；人员可编辑的排班和别名直接从云端读取。
队伍认证使用本地环境中的摘要映射，绝不写入智能表格；禁止重新导入旧镜像覆盖人工编辑内容。
