发布时填写：测试机器人／赛事空间（仅本地配置引用）、知识来源及版本、实际工具名、角色和范围、验证用例、证据位置、Owner、Reviewer、Git commit、发布时间、回退 commit。任何一项未完成都保持候选。

发布流程：确认测试资料 → 同一企微渠道逐项验证 → 双人权限验证 → Owner/Reviewer 审核 → 装载同一 commit 的提示和五项 Skills → 回归 → 逐项停止重复兼容查询。全程保持选手与工作人员认证分离。

资料登记要求：每份文档记录 `doc_id`、标题、角色、版本、生效日期、Owner、来源。至少覆盖《报名与赛制》《作品提交规则》《志愿者签到 SOP》《异常升级流程》。未批准文档保持待确认；仓库示例规则不会自动升级为正式知识。

资料库解释规则；提交截止时间等硬规则由 Arena 配置和代码执行。两者冲突时暂停对应规则发布并交 Owner 确认。普通业务状态以智能表格为准，作品正文以 GitHub 为准。反馈、成员、内部备注和工单数据的权限必须在数据源或可信后端执行，不能依赖 Prompt 过滤。
